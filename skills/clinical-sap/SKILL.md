# Clinical SAP

## Workflow

1. Identify the study design, objective, estimand, endpoint hierarchy, and analysis population.
2. Request protocol details when endpoints, time windows, or intercurrent events are ambiguous.
3. Choose the closest template from `templates/`.
4. Make the SAP explicit about models, covariates, missing data, multiplicity, sensitivity analyses, and software.
5. Flag any choices that require clinical, regulatory, or sponsor confirmation.

## Required Checks

- Define primary and secondary endpoints with derivations and time windows.
- Define all analysis populations.
- State sidedness, alpha, confidence interval level, and multiplicity control.
- Specify how protocol deviations, intercurrent events, and missing data are handled.
- Include planned tables, listings, and figures.

## Output Style

Use precise SAP language. Separate confirmatory analyses from exploratory analyses. Avoid claiming regulatory adequacy unless the user provides the applicable regulatory context.
